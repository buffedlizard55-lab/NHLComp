# NHLComp

An autonomous NHL betting-strategy **research, discovery, backtesting, forward-testing and
paper-trading** platform. It finds its own data sources, generates its own strategy
hypotheses, tests them, and paper-trades the survivors — logging every simulated wager with
its price, its source and its verification status.

> **Paper trading only.** No real money is wagered and this repository contains no
> order-placement code. There is no function anywhere in `src/` that can submit an order to
> an exchange or a sportsbook.

---

## Why the numbers on the site look the way they do

Read this before reading any result.

* **No verified historical sportsbook odds exist in this project.** The aggregator APIs that
  sell them require a paid key, and none was invented. So there is no moneyline closing-price
  backtest anywhere here.
* **Kalshi's historical candle endpoint returned HTTP 404** at both documented path shapes
  (verified 2026-09-20 against a known settled contract). There is therefore no intraday price
  history, and no line-movement or live/in-game backtest is attempted.
* What *is* available from Kalshi is settled contracts carrying a pre-settlement bid/ask, real
  volume and the official result. Bets built from those are labelled **BACKTEST** and stamped
  `verification_status=single_source_timing_unverified`, because Kalshi does not document the
  exact timestamp behind its `previous_*` fields.
* Everything priced from a live quote is labelled **FORWARD TEST** and settles later.
* Where no price feed exists at all, the backtest reports **predictive accuracy only** — hit
  rate, lift over base rate, log loss, Brier — and stores `data_sufficient=0`. It never
  invents a profit figure.

The two labels are never merged. `bets.test_mode` is either `BACKTEST` or `FORWARD TEST`.

## Architecture

```
src/nhlcomp/
  http.py         HTTP client, content-addressed cache, provenance capture
  store.py        SQLite schema + append-only ledger + audit trail
  sources/
    registry.py   the permanent NHL DATA SOURCE REGISTRY
    nhl.py        api-web.nhle.com and api.nhle.com/stats/rest adapters
    kalshi.py     Kalshi public market-data adapter
  ingest.py       acquisition; stores raw payloads with SHA-256 digests
  features.py     point-in-time features (rest, travel, density, streaks, pace)
  models.py       Elo, Poisson, logistic, home-ice constant, calibration metrics
  discovery.py    autonomous hypothesis generation and chronological search
  strategies.py   strategy rules, Kelly sizing, execution signals
  backtest.py     accuracy-only backtesting with leakage assertions
  paper.py        execution model, settlement, open positions
  analysis.py     PnL, ROI, drawdown, CLV, Wilson intervals, breakdowns
  verify.py       irregularity queue and cross-source validation
  site.py         static GitHub Pages generator
  pipeline.py     end-to-end orchestration
  cli.py          command-line interface
```

**Standard library only.** No third-party runtime dependency, so CI cannot fail on a
dependency and the whole thing runs anywhere Python 3.10+ does.

## Quick start

```bash
make test            # 66 unit tests, no network needed
make probe           # HTTP-probe every registered source and record the verdict
make ingest          # pull live data (needs outbound network)
make run             # models -> discovery -> backtest -> forward -> settle -> verify
make site            # regenerate docs/ from the ledger
make report          # plain-text competition status
```

`python -m nhlcomp run --offline` replays the response cache instead of touching the network.

## The competition

Every strategy gets a username, a strategy ID, a version, a virtual bankroll, an explicit
hypothesis / data / entry / price / settlement rule, and its own ledger. Strategies are never
overwritten — a change creates `v2`, so an edit can be judged on whether it actually helped.

Strategy names are generated by the system (`NHL_GEN_AWAY_WIN_PCT_L10`, `NHL_B2B_FADE`, …),
not supplied by a human.

## Guarantees the code enforces

| Claim | Where it is enforced | Test |
|---|---|---|
| No look-ahead bias | `features.FeatureBuilder._prior` cuts off at the game's own start time | `test_no_future_information_leaks`, `test_three_in_four_nights_is_detected` |
| Elo prior is not leakage | seeded from the **previous** season's points % | `stage_models` |
| Bets are append-only | `Store.record_bet` refuses a duplicate `bet_id` | `test_record_bet_is_append_only` |
| Corrections are audited | `settle_bet` / `amend_bet` write before/after rows | `test_resettlement_is_recorded_not_silent` |
| No profit without real prices | `Backtester.run` stores `pnl=NULL`, `data_sufficient=0` | `test_backtest_without_price_data_reports_no_pnl`, `test_04_*` |
| No unlimited liquidity | `simulate_fill` caps at `yes_ask_size_fp`, records the unfilled remainder | `test_partial_fill_when_stake_exceeds_liquidity` |
| Strategies never chase | bet only when `ask <= model_prob - min_edge` | `test_05b_strategy_refuses_a_price_that_is_not_value` |
| Conflicts are recorded, not resolved | `Verifier.cross_validate_*` writes both values | `test_conflicting_sources_are_recorded_not_resolved` |
| Small samples say so | Wilson interval beside every win rate | `test_wilson_interval_is_wide_for_small_n` |

## Data sources

See **Data Sources** on the site, or `source_registry` in the ledger. A source is only marked
`verified` after an automated probe is written to `source_verification`. "Free tier" is never
recorded as free: anything needing a key, a trial or paid credits is marked `freemium`.

Verified reachable from the development environment on 2026-09-20:

| Source | Verdict | Evidence |
|---|---|---|
| `api-web.nhle.com/v1` | reachable | live scoreboard JSON incl. 2026-09-19 results |
| `api.nhle.com/stats/rest/en` | reachable | 62 franchise rows |
| `api.elections.kalshi.com/trade-api/v2` | reachable | live `KXNHLGAME` contracts with bid/ask/size |
| `site.api.espn.com/.../nhl/injuries` | reachable | dated injury entries |
| `archive-api.open-meteo.com` | reachable | hourly historical weather, no key |

Flagged or rejected:

| Source | Status | Reason |
|---|---|---|
| `api.nhl.com/api/v1` | flagged | two fetch attempts failed from the sandbox; may be egress, not death — CI re-probes |
| `statsapi.web.nhl.com/api/v1` | flagged | fetch failed; would have been the only first-party arena-coordinate source |
| Kalshi candles | rejected | HTTP 404 at both documented path shapes |
| The Odds API | rejected | paid key required; none invented |
| Natural Stat Trick / MoneyPuck / Evolving-Hockey | rejected | no API; scraping conflicts with site terms; xG is a model output, not source data |

## Known limitations

* **No arena coordinates.** The legacy NHL venue host was unreachable, so travel is derived
  from published venue `venueUTCOffset` values rather than invented lat/lon. `venues.lat` and
  `venues.lon` are deliberately NULL.
* **No goalie, lineup, EDGE or prop ingest at scale.** Goaltending, line-matchup, tracking and
  player-prop strategies exist as recorded hypotheses awaiting forward tests — not as results.
* **Preseason Kalshi liquidity is thin.** Several contracts show zero size on both sides; those
  are recorded as `insufficient_liquidity` and not traded.
* **No intraday prices**, so live/in-game and line-movement strategies cannot be backtested.
